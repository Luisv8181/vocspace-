# VocSpace Resource Ecosystem

VocSpace should treat external organizations as ecosystem nodes, not competitors by default.

## Resource Categories

| Category | Example | VocSpace role |
|---|---|---|
| Accommodation knowledge | JAN | Source accommodation patterns and guidance |
| Digital remediation | TechA11y | Route suitable web accessibility cases |
| Standards | WCAG | Ground technical accessibility requirements |
| Legal guidance | EEOC / ADA resources | Provide authoritative context |
| Assistive technology | AT vendors | Identify implementation options |
| Human expertise | Accessibility consultants | Route complex cases |
| Public services | VR agencies | Connect eligible employment supports |
| Developers | Coding teams/agents | Implement technical solutions |

## Resource Record

Each resource should eventually have:

- name
- URL
- organization type
- domains
- capabilities
- populations served
- geographic scope
- delivery model
- cost model
- evidence/source links
- last verified date
- accessibility of the resource itself
- referral instructions

## Provenance Rule

VocSpace must distinguish:

**Source says:** factual information directly supported by the resource.

**VocSpace infers:** a contextual recommendation based on the source.

**Implementation suggestion:** a proposed way to apply the concept.

**Legal/professional guidance:** information that should remain attributed to the authoritative source.

This is especially important when AI is involved.
